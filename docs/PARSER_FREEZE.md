# Physical parser baseline — 2026-11-05

2026-11-23 사용자 승인으로 파서 로직 동결이 해제되었다. 현재 표 구조 작업의 허용 범위는
머리글·경로 후보와 표 조각 연결이며, 물리 격자(PhysicalTableIR), 원문과 기존 KB 결과는 바꾸지 않는다.
아래 기록은 2026-11-05 동결 당시의 기준이다. manifest·ZIP·KB 결과를 덮어쓰지 않으며,
이번 구조 변경에서도 물리 보존 검사를 그대로 실행한다.
의미 분석 및 표시 개선은 별도 후보/실행으로 진행하며 기존 결과에 덮어쓰지 않는다.
이 동결은 의미 정확도 승인이나 금융 Fact 발행 승인이 아니다.

## 승인된 폴더 분리와 주석 추가

2026-11-09 사용자가 역할별 폴더 분리와 각 파일의 한글 주석 추가를 요청했다.
이 승인은 파일 이동·import 경로 갱신·주석 추가에 한정하며 물리 알고리즘과 KB 기준
결과 변경을 허용하지 않는다. 현재 파일 배치는 [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)를 따른다.
추가 승인된 책임별 정리로 추출·표 분석·문서 조립은 `parser/` 아래로 이동한다.
이때도 원본 manifest/ZIP과 알고리즘은 보존하며 고정 이동표로 원본과 비교한다.

기존 `manifest.json`과 `baseline.zip`, KB 산출물은 그대로 유지한다.
`scripts/check_parser_freeze.py`는 명시된 이동표로 현재 파일을 찾는다.
원본 해시가 달라진 Python 파일은 해시로 검증된 기존 ZIP의 소스와 비교하여,
승인된 import 경로만 이전 이름으로 환산한 AST가 동일한지 검사한다.
주석·배치 변경은 허용하지만 계산식·상수·함수·모델·문자열·의존성 변경은 실패한다.
새 물리 패키지의 `__init__.py`에는 실행 로직을 허용하지 않는다.
KB 결과와 기준 ZIP은 계속 바이트 단위 SHA256이 일치해야 한다.
새 해시를 manifest에 기록하여 검사 실패를 숨기지 않는다.

- 기준 실행: `331a24bbcd404065b06605ee777fc3b2`, KB 전체 8쪽.
- 소스 및 결과 사본: `reports/parser-freeze-20261105/baseline.zip`.
- 소스 267개, 보호 대상 코드 22개, 기준 결과 6개 해시:
  `reports/parser-freeze-20261105/manifest.json`.
- 검사: `.venv/Scripts/python.exe scripts/check_parser_freeze.py`.
- 의미 분석/표시 파일은 사본에 포함하되 물리 코드 보호 목록에서 분리했다.
- 파일 권한 잠금은 아니다. 실행 중 서버의 작업 중단은 확인하지 못했다.
  localhost API 접근이 WinError 10013으로 제한됐다. 자동 반영 잠금 완료로 해석하지 않는다.

## 동결 시점의 KB 4쪽 진단

다음은 기준 산출물에 대한 당시 관찰이다. 새 실행의 결과와 구분하며 현재 코드 위치는
[PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)를 따른다.

물리 IR은 바깥 표 1개와 안쪽 표 1개를 분리했다. 내부 표는 8행×3열,
18셀이고 계약기간 36개월/60개월의 행 병합은 각각 2행/3행으로 보존된다.

선택한 `physical001/cell0012`는 값이 아니라 행 라벨이다.
저장된 row_tree에는 이미 `계약기간 60개월 이하 → 경과기간 24개월 미만`이 있다.
`services/documents.py`의 export_document는 값의 cell_mappings만 조회하므로
행 라벨에 매핑이 없으면 row_path/col_path를 비워서 내보낸다.
이 때문에 화면의 "아직 연결되지 않았습니다"가 저장된 행 계층까지 없는 것처럼 보인다.

별도 의미 분석 문제도 있다. 당시 `table_understanding/semantic.py`
(현재 `parser/structure/analyzer.py`)는 본문의 세로 병합에서
stub_columns=2를 추정하고, 이 고정 경계를 가로지르는 셀을 unknown으로 남긴다.
2~3열을 덮는 헤더 `특별중도해지 이자율`과 첫 두 본문 값이 해당한다.
결과적으로 column_tree가 비었고 나머지 값 5개의 열 경로도 비었다.
중첩 물리 추출 실패와 다른 문제이며 KB 문자열 특례로 해결하지 않는다.

## 다음 의미 개선 범위

1. 행/열 라벨 선택 시 해당 축 트리에서 자기 위치를 표시한다.
   값 셀의 경로와 라벨 자신의 계층을 구분하고, 라벨에 양 축을 억지로 부여하지 않는다.
2. 단일 stub 경계가 아니라 행별 라벨 깊이와 병합 헤더 범위를 검사한다.
   경계를 가로지른 셀을 일괄 값/헤더로 바꾸지 않고 충돌·음성 사례를 검사한다.
3. 값 셀의 후보는 계약기간 → 경과기간의 행 경로와 이자율 열 제목을 연결한다.
   외곽 설명/이전 페이지 문맥은 별도 context로 유지한다.
4. 동결 IR로 후보 생성, 원본 셀 ID/병합/텍스트 불변 검사, 범용/음성 회귀 후
   새 비교본에서 사람이 검토한다. 기존 실행 및 오류 의견은 보존한다.

이번 작업은 동결 및 원인 진단이다. 의미 로직/화면 변경과 재채점은 아직 하지 않았다.
