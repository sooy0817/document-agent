# 테스트 기록 운영과 정확도 개선 계획

2026년 10월 20일 기준. 남원은 개발·회귀용이며 신규 5기관은 이미 열람한 진단 자료다. 남평은 최종 Holdout으로 열지 않는다.

## 현재 구조

1. **PDF → DocumentIR**: PyMuPDF가 원문 문자와 좌표를 추출한다. 스캔에서 Native Text가 없으면 OCR 없이 문자를 만들지 않는다.
2. **PhysicalTableIR 2.1**: 선과 셀, 병합 범위, observed/inferred/unresolved 경계를 기록한다.
3. **StructuredTableIR**: 물리 배치에서 행·열 Tree와 값 셀의 경로 후보를 만든다.
4. **Semantic Overlay**: Rule 및 별도 실험의 저장된 LLM 응답으로 의미 관계 후보를 기록한다. ID Binder와 Patch Validator가 원본 참조·충돌을 검사한다. 현재 기본 실행은 로컬 Rule-only이고 새 LLM 호출은 없다.
5. **수정 후보**: 병합 행 라벨의 연결을 보완하고 의심 부모는 격리한다. 기존 결과를 덮어쓰지 않으며, 격리를 정상 루트로 확정하지 않는다.
6. **수치 검증과 사람 검토**: 후보 집계 범위의 합계를 계산하고 원본과 비교한다. 합계가 맞아도 행·기간·단위와 포함 범위의 의미 검증은 별개다.
7. **정답 revision → 동일 기준 재평가 → 실험 기록부**: 검토가 끝난 범위만 별도 정답 개정에 반영한다. Raw Extraction과 미확정 관계는 계속 보존한다. DB 적재와 확정 Financial Fact 발행, RAG 임베딩·답변 실험은 보류 중이다.

## 기록부에서 할 수 있는 일

- 현재 결과 9개를 최초 등록했다: 남원 v3/v4, 남원 검산, 5기관 실행, 운주 검산. 모든 과거 실험을 자동 발견·등록했다고 주장하지 않는다.
- 결과 JSON·코드 동결표·정답 및 관련 증거를 SHA-256 기준 스냅샷으로 보관한다. 같은 결과를 다시 등록하면 중복되지 않고, 결과가 바뀌면 새 실행 기록이 된다.
- 기존 코드 동결 자료가 있는 경우 연결한다. 현재 코드로 과거 실행 버전을 대신하지 않는다.
- 기록부의 HTML과 catalog는 재생성 가능한 목록이며, runs/objects/reviews/queues는 기존 내용을 덮어쓰지 않는다.
- 검토 JSON은 검토자, 정답 묶음 해시, 항목 ID, 판정, 사유를 포함한다. 잘못된 묶음·중복 항목·설명 없는 수정 판정은 가져오기에서 거절한다.
- 가져오기는 **사람 검토 이벤트 추가**까지만 한다. 실제 Golden 개정과 재평가는 별도 단계다. 과거 판정을 바꾸면 이전 기록을 지우지 않고 새 검토 이벤트를 추가한다.
- 이후 새 실험은 등록 CLI를 실행해야 누적된다. 백그라운드 자동 감시나 정기 실행은 설정하지 않았다.

## 사용자가 지금 확인할 부분

새 기록부에 12개 항목을 구성했다. 기존 화면 전체를 다시 검토할 필요는 없다.

| 항목 | 수 | 확인 내용 |
|---|---:|---|
| 남원 p45·46 남은 값 경로 | 4 | 충당금 금액의 실제 셀 영역, 비율 B/A가 특정 열에 속하는지 독립 값인지 |
| 남원 격리된 부모 | 5 | 기존 부모가 실제로 맞는지. 미확정 분리의 타당성과 정상 루트 승인은 구분 |
| 운주 p17 소계·합계 | 3 | 두 연도의 합산 대상이 빠짐없이 맞는지, 소계·상세 중복이 없는지 |

각 항목에 원본 이미지, 현재 판단, 비교 결과와 질문이 있다. 동의/수정 필요/보류와 의견을 기록하고 JSON을 내보내 전달한다. 브라우저 저장은 임시 초안이며 정식 파일 기록과 구별한다. 현재 정식 검토 이벤트를 임의로 만들어 넣지 않았다. 이전 남원 전체 Tree 확인 기록은 당시 검토 범위 그대로 별도 증거로 보존했다.

## 수치 검증을 늘리는 순서

| 단계 | 테스트 | 실행 조건 | 자동 판정과 보류 기준 |
|---|---|---|---|
| 현재 | 소계·총계 | 검토용 합산 범위가 명시됨 | 대시와 확인된 빈 셀은 검산만 0. 셀 미연결은 미확정. 정확 합산 비교 |
| 다음 A | 기초 + 증가 − 감소 = 기말 | 네 열의 기간·단위·역할을 원본에서 주석 | 차이와 원문 보존. 역할 추론이 모호하면 계산 결과와 역할 후보를 분리 |
| 다음 B | 당기 − 전기 = 증감 | 비교 기간·부호·범위 일치 | 금액 증감과 비율 변화(%p)를 구별 |
| 다음 C | 구성비·충당금 비율 | 분자·분모·표시 자릿수·단위 확인 | 분모 0 기권, 표시 반올림 구간 검사. 임의 고정 허용오차 금지 |
| 다음 D | 집계 범위 후보 검산 | 표·패널·동일 열·기간 안에서 구조적으로 제한한 후보 | 하나의 후보가 맞아도 제안만 생성. 여러 범위가 맞으면 복수 후보로 유지 |

숫자 조합을 무제한 탐색해 합계가 맞는 범위를 정답으로 삼지 않는다. 0인 행은 넣거나 빼도 합계가 같으므로 숫자만으로 소속을 확정할 수 없다. 같은 값의 반복, 우연히 맞는 합계, 빈칸/대시/음수, 상세와 소계 중복, 잘못된 기간·단위, 반올림 경계, 분모 0, 원문 자체 오류를 합성 음성 테스트에 포함한다.

신규 계산 종류마다 원본을 독립적으로 읽어 만든 소규모 주석과 합성 오류 사례를 먼저 마련한다. 자동 판정의 정밀도, 검토 필요 비율, 잘못 확정한 관계 수를 따로 측정한다. 계산 실패를 모두 파서 실패로 집계하지 않는다.

## 성능 개선 우선순위

1. **셀 대응과 독립 값**: 남원 잔여 4건. 금액·기간·단위를 잘못 연결하는 문제를 가장 먼저 처리한다.
2. **기권 지표**: 현재 후보 경로 229/233에는 부모 격리 후 경로가 맞아 보이는 사례가 포함된다. 확정 정답 수, 기권 수, 오연결 수를 분리한 평가가 필요하다.
3. **복수 항목명 열과 좌우 병렬표**: 운주 p17과 김천 p46에 실제 존재한다. 이번 단일 열 수정의 적용 범위를 넘으므로 별도 범용 규칙과 음성 테스트가 필요하다.
4. **탐지 오탐**: 페이지 번호 상자 등은 기하 통과와 무관하게 비표로 분류할 기준이 필요하다. 원본에서 전체 표 목록을 만들기 전 탐지 Recall은 N/A다.
5. **스캔**: 고성·예산은 Native Text가 없다. OCR 도입 전 의미·수치 정확도를 평가하지 않는다. OCR은 이번 작업에서 추가하지 않았다.
6. **검증된 의미 개선 후 RAG**: 새 문서의 독립 주석으로 일반화를 확인하고 나서 Raw/Table/Tree/Hybrid 검색 비교를 재개한다.

## 재현과 CLI

```text
python scripts/build_evaluation_ledger.py
python -m doc_understanding.eval.ledger verify
python -m doc_understanding.eval.ledger import-review --file 검토결과.json
python scripts/build_evaluation_ledger.py
python -m doc_understanding.eval.ledger register --file 실행등록명세.json
```

등록 명세에는 title, dataset_role, result_kind, metadata, artifacts(워크스페이스 상대 경로 목록)가 필요하다. 평가 입력/정답/코드동결/설정/결과/테스트 로그를 함께 등록한다. 새 결과 파일과 등록 명세를 만들고 등록한 후 목록 화면을 갱신한다.

표시 시간은 UTC로 저장하고 현지 해석 시 Asia/Seoul을 사용한다. 등록 시각은 실행 시각과 구별한다. LLM 토큰·비용·지연은 실제 실행 시에만 실측값으로 기록하며 미실행은 N/A다.

## 현재 수치의 한계

남원 합계 40건 중 39건 일치, 1건 차이 1. 운주 일부 범위 6건 중 5건 일치, 1건 차이 1. 이는 범위와 표시 숫자 간 산술 증거다. 새 기관 전체 Tree 정확도나 RAG 정확도가 아니다. 신규 5기관은 259페이지 중 문서당 6페이지, 총 30페이지 물리 검사이며 스캔 2개를 포함한다. 전체 문서 정확도를 검증했다고 표현하지 않는다.

## mapping-holdout 사람 검토

1. 검토 시작 시 정답 세트의 Git 커밋과 문서 ID, 평가 대상 manifest를 기록한다. 검토 화면의 `/mapping#set=mapping-holdout-v1`에서 해당 문서·쪽·물리 표 번호를 연다. 오확정이 나온 표, 담는 칸·중첩 표, 나머지 표 순으로 진행하되 완료 분모는 세트 전체로 유지한다.
2. 원본 PDF 쪽 그림 또는 HTML을 먼저 읽는다. 행·열 위치, 원문, 병합 범위로 칸을 식별하고 역할과 행·열 머리글을 바깥에서 안쪽 순서로 적는다. 담는 칸이면 포함 본문과 하위 표의 위치·부모도 확인한다. 그 뒤 화면의 기대값과 비교한다.
3. 차이가 있으면 해당 셀의 기대값을 수정하고 메모에 원본 쪽, 행·열, 수정 근거를 남긴다. 셀별 ‘이 셀의 기대값을 내가 확인했다’를 체크하고 표를 저장한다. 원문이 열리지 않거나 둘 이상의 경로가 가능하면 확인 표시를 해제하고 이유를 적어 보류한다. 표 전체 확인 표시는 모든 셀을 원문과 대조했을 때만 사용한다.
4. 기존 오확정 셀과 판정이 엇갈린 셀은 두 번째 사람이 동일한 원본에서 독립적으로 확인한다. 합의 결과와 검토자·일자를 기록한다. 판독 불가 항목을 점수 개선 목적으로 채점 제외로 바꾸지 않는다.
5. 검토한 정답 세트의 diff에서 변경 셀과 부모 참조를 확인한 후 버전을 고정한다. 이전·새 파서 출력을 **같은 정답 버전**으로 각각 채점한다. 보고서에는 전체 셀, 사람이 확인한 셀, 보류 셀, 역할·경로 일치율, 새로 잘못 확정한 셀 식별자를 기록한다. 모든 셀이 확인되어야 세트 전체를 사람 검토 완료로 표시한다. 이 세트는 개선 과정에서 사용한 회귀 자료다.
