# ADR-079: 질의 시점 질문 이해 에이전트

- 상태: 채택
- 날짜: 2026-11-10

## 배경

현재 질문 분해(assessment)는 검색이 끝난 뒤 답변을 검사할 때만 쓰인다. 검색은 질문 문장 하나를
키워드·벡터로 던지므로 "확정급여형에서"가 적용 범위 조건이고 "고정금리형 일 단위 계좌"가 열 이름이라는
구분을 쓰지 못한다. 벡터 검색은 `24개월 이상`과 `미만` 같은 경계 표현을 잘 구분하지 못했다.

## 결정

1. 계획 후 실행(plan-then-execute) 구조로 둔다. LLM은 질문을 계획으로 바꾸는 단계와 기존 답변 단계에서만 쓴다.
   도구 선택·실행 순서는 코드가 정한다. 자율 반복 루프는 두지 않는다.
2. 계획은 질문 원문 구간에 고정된 요구 사항 목록(역할: 적용 범위·항목·조건·기타)과 1~4개의 검색어다.
   질문에 없는 인용 구간은 거부한다.
3. 도구는 모두 결정적이고 읽기 전용이다.
   - 검색: 기존 lexical/dense/hybrid
   - 표 구조 조회: 검색된 표의 행·열 경로와 적용 범위
   - 구조 일치 조회: 요구 사항 문구를 행·열 라벨(공백 무시)과 비교해 값 셀을 고른다
   - 적용 범위 확인: 구조 검토 후보(ADR-078)의 범위 문구와 대조
4. 구조 일치로 찾은 셀을 근거 앞쪽에 두고, 기존 근거 복원 결과로 문맥을 보충한다. 답변과 인용 검사는 기존
   `generate_answer`를 그대로 사용한다. 미확정 매핑의 답변 차단도 그대로다.
5. 답변 검사에서 근거 부족으로 판단된 요구 사항이 있으면, 그 질문 구간으로 한 번만 다시 검색한다.
6. 계획·도구 호출·선택 근거를 실행 폴더에 남긴다. 계획 호출과 답변 호출의 비용 한도는 따로 둔다.

## 대안과 결과

- 모델이 도구를 자유롭게 고르는 tool-calling 루프: 호출 수와 비용 예측이 어렵고 검증이 어렵다. 계획이
  잘 맞지 않는 사례가 평가에서 확인되면 제한된 형태로 다시 검토한다.
- 질문을 규칙으로 파싱: 분야·언어가 바뀌면 깨진다(ADR-076). 의미 분해는 모델에 맡기고 코드는 인용 고정만 검사한다.
- 구조 일치는 라벨 문자열 비교라서 동의어를 찾지 못한다. 검색 결과로 후보 표를 먼저 좁히고, 일치가 없으면
  기존 검색 근거로 진행한다.
- 계획 모델이 요구 사항을 빠뜨리거나 잘못 나눌 수 있다. 계획 통과는 의미 정확도 승인이 아니다.
