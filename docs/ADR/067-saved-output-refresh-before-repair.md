# ADR-067 — 코드 수정 전에 저장본과 최신 실행을 비교

2026-11-04. 기존 IR·PDF·과거 실행은 변경하지 않는다.

## 발견한 병목

KB 검토 의견은 오래된 화면 저장본을 가리켰다. 이미 반영된 ADR-055 개선을 다시 실행하면 3쪽의 중첩 표시가 1개에서 2개로 바뀐다. 이 상태에서 새 코드 생성을 먼저 호출하면 이미 해결된 부분에 비용을 쓸 수 있다.

## 실행 방식

기본 `local_refresh`: 새 오류 의견 → 버전 있는 검토 요청 → 현재 코드/원본 해시 동결 → 네트워크 없는 컨테이너에서 전체 PDF 재추출 → 저장본과 페이지별 비교 → 사용자 원본 확인. 동일 검토 요청은 중복 접수하지 않는다. 과거 요청은 선택해서 접수하며 실패는 무한 재시도하지 않는다. 서버가 실행 중일 때 큐를 처리한다.

선택 `code_patch`: 기존 제한된 수정안 생성·격리 테스트·같은 PDF와 등록 회귀 자료 재실행 경로를 유지한다. 유료 생성은 별도 실행 방식이다. 기본 파서 자동 교체, 새 PDF 자동 수집, 정답 자동 승인은 이번 변경에 포함하지 않는다. 허용된 수정 파일·수정 이유·diff와 실패 기록을 남긴다.

## 기록과 표시

- 실행마다 별도 `attempt-N`, 원본/코드 해시, 요청, 입력 자료 목록, 실행 로그, 전후 JSON, 결과 저장.
- 과거 저장본/현재 실행과 신규 수정 전/후를 구분한다. 이전 코드 버전을 모르면 모른다고 기록한다.
- 물리 셀, 화면 중첩 표, 미해결 포함 관계, 양축 경로 후보, 원문 span 보존을 문서/페이지별로 표시한다.
- 셀 ID의 재번호 부여도 변경에 포함될 수 있으므로 변경 셀 수를 오류율로 해석하지 않는다.
- 비교 기준이 없으면 추출 성공만 보고하며 회귀 성공으로 계산하지 않는다.
- 실패 실행도 이력에 남긴다. API 없는 실행은 0원, 과거 사용량 미기록은 비용 미확인으로 분리한다.
- 유료 한도는 요청 수가 아닌 호출 시도 수로 센다. 재시도도 포함한다.

## 실제 실행

`work/document-explorer/parser-repairs/7fc6ce065a2f4ecb95a2602c4ed37215/attempt-5/result.json`.

| 자료 | 실제 관찰 | 판정 한계 |
|---|---|---|
| KB 전체 8쪽 | 원문 span 보존. 물리 셀 193→217. 3쪽 중첩 표시 1→2, 미해결 포함 관계 2→1. 4쪽 중첩 표시 0→1 | 2쪽 포함 관계 2건 미해결. 전체 의미 정답 승인 아님 |
| 하나은행 | 원문 span 보존. 물리 셀 292→304. 3쪽 변화 | 과거 저장본과의 차이이며 새 수정 효과가 아님. 추가 셀/ID 변화의 원본 확인 필요 |
| 강동농협 | 추출 실행 완료 | 해당 원본 해시의 과거 화면 저장본 없음. 이번 실행에서 전후 회귀 확인 불가 |

모델/API 호출 0회. 기존 실패 시도와 비용 기록은 보존했다. 33개 Python 검사와 19개 JavaScript 검사 통과는 자동화/검토 기능 검사이며 PDF 의미 정확도 점수가 아니다.

## 남은 작업

1. 원본 참조가 있는 대상별 성공 조건을 추가해 단순 변화와 올바른 개선을 구분.
2. 최신 실행에도 남는 오류만 코드 수정 후보 생성으로 전달; 같은 정답 참조로 전후 평가.
3. 검토하지 않은 새 PDF를 사전 등록해 일반화 평가. 현재 등록 자료로 범용성 확정 금지.
4. 회귀/반례 검사와 사람의 검수를 거친 수정 후보의 기본 파서 승격 절차는 별도 구현.
