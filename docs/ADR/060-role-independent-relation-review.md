# ADR-060: 설명 셀의 역할과 적용 관계를 독립 판단

2026-11-04. 기존 원본/IR/결과를 보존하는 명시적 실험이다. 문서별 예외를 추가하지 않는다.

## 문제

ADR-059에서는 역할과 축을 같은 출력으로 만들고 description/header는 축이 없어도 된다고
안내했다. KB의 긴 설명 셀과 왼쪽 항목 사이 관계가 비었고 Judge도 같은 이유로 동의했다.
역할 분류가 관계 검수를 건너뛰는 근거가 되면 비수치 문서의 검색 문맥이 사라진다.

## 변경

`demo/review_roles.py`: classify_roles → infer_relations → judge_relations → validate_relations_and_storage.
역할 출력과 관계 출력은 별도 계약이다. 관계 판단과 Judge는 역할 모델의 결과를 받지 않는다.
값/설명/제목 모두에 적용 항목과 양축 관계를 질의한다. 끝에서 역할을 표시용으로 결합한다.
원본 수집, 이미지, 선택 대상은 ADR-059의 동일 입력을 재사용한다. 원본 JSON 계약은 그대로다.

같은 페이지의 왼쪽/위쪽 정렬 셀을 기하 후보로 제시한다. Judge는 각 후보를 required /
not_required / insufficient_evidence로 검토하고 인용과 이유를 남긴다. 위치는 의미 정답이
아니다. 관계가 불필요한 이웃은 제외할 수 있다. 후보를 건너뛰면 coverage 검사로 보류한다.
required로 판정한 제목이 출력 경로에 빠지면 REQUIRED_HEADER_MISSING을 남긴다. Judge가
필요성을 잘못 판단할 가능성은 여전히 있으며 코드 검사만으로 완전한 의미 정답을 보장하지 않는다.

대상 원문은 target_quote 필드로 별도 반환한다. 코드가 이 인용을 같은 셀 ID로 축 근거에
연결하고 정확한 원문 부분 문자열인지 확인한다. 원문을 새로 생성하거나 이전 답변을 고치지 않는다.
최대 12대상/160기하 후보, 모델 호출은 일반 실행당 3회다. 후보별 검수 출력이 4,500토큰을
초과할 수 있어 이 실험 어댑터만 16,000토큰 상한을 사용하며 버전에 이를 명시한다.
기존 어댑터/실험 코드는 변경하지 않는다. 항상 semantic_verified=false/training_ready=false.

## 실험

KB·하나은행·농협 개발/회귀 3건을 동일 선택 영역/이미지로 실행한다. KB의 과거 후보를 그대로
새 Judge에 넣는 별도 1회 검수를 추가해 생성기와 Judge 효과를 분리한다. 총 10회 상한을 두고
모든 응답·비용·Trace·코드 동결 해시를 별도 저장한다. 자동 큐 설정은 변경하지 않는다.
신규 Holdout, 전체 문서 Tree, 모든 주석 적용 범위의 검증으로 확대 해석하지 않는다.

실제 결과: `reports/review-roles-20261104/comparison.html`.

## 동결 후 실제 결과

- 선택한 KB 긴 셀 2곳의 왼쪽 항목 경로는 이전 모델 후보 0/2에서 2/2로 생성됐다.
  하나은행/농협의 직접 행·열 ID 4개는 유지됐다. 원본 시각 검토 초안이며 승인 Gold가 아니다.
- Judge 개선은 미완료다. 이전 KB 후보 검수는 27기하 후보 중 4개만 반환했고, 올바른 누락
  2개와 잘못 요구한 위아래 관계 2개가 섞였다. required 판정과 이유도 모순됐다.
- 새 KB 후보 검수도 4/27개, 인용 말줄임과 양 끝 인용 누락이 있었다. 하나은행은 2/2개를
  검토했으나 coverage의 대상 인용 누락과 헤더 조각 연결 검토가 남았다. 농협은 8/8개를
  검토했으나 900만원이라는 별도 값 셀을 행 제목으로 요구하고 축별 결론을 중복 반환했다.
- 모두 held를 유지한다. 관계 후보 생성 개선을 전체 검수·표·RAG 정확도 개선으로 세지 않는다.
- GPT-4.1 총 10회, 추정 $0.301986. 자동 큐/기본 경로/파서/원본 IR을 변경하지 않았다.
- 관련 테스트 69개: 68통과, 1개 Windows asyncio 초기화 오류. 해당 항목 재실행 통과.
  Mock 사용, 테스트 실제 API 0회. XML과 실행/Trace 감사 결과를 보고서에 보존한다.

이전 후보 재검수에는 기존 role 필드도 보존됐으므로 새 역할 배제 입력과 완전히 동등한
Judge 단독 A/B는 아니다. 새 후보 출력 계약과 기하 후보 제공도 함께 바뀌었다. 이번 결과로
역할 분리 하나만의 효과나 미사용 문서의 일반화 성능을 확정하지 않는다. 다음 실험에서는
논리적 표 범위의 후보 제한, 병렬 값 문맥/헤더 관계 구분, 축 결론/후보 검토 책임 분리를
검토한다. 이번 동결 코드에 사후 적용하지 않는다.
