# ADR-077: 원문 연결을 유지하는 임베딩 저장과 하이브리드 검색

## 결정

파서와 CanonicalDocument는 유지하고 RAG 검색 항목에 별도의 pgvector 벡터를 연결한다.
기본 검색은 기존 lexical이며 dense·hybrid는 명시적으로 선택한다. 초기 비교 모델은
`text-embedding-3-small`, 1,536차원이며 모델·차원·비용은 호출자가 설정할 수 있다.
이 선택은 해당 모델의 범용 우수성에 대한 평가 결과가 아니다.

`rag.entry_embedding`은 run·entry·profile ID를 키로 사용한다. 프로필은 공급자·모델·차원·
운영자 지정 세대·입력 표현 버전의 해시다. 입력 텍스트 SHA256과 검색 인덱스 버전도 저장한다.
같은 프로필과 원문만 재사용하며 저장 시 현재 검색 항목과의 일치를 확인한다. 배치 내 일부
항목이 사라지거나 바뀌면 전체 배치를 롤백한다. 완료 배치는 재실행에서 재사용한다.
원본 검색 항목 재색인으로 삭제되는 벡터는 파생 캐시이며 원문 IR 삭제를 뜻하지 않는다.

문서와 질문은 동일 프로필로 임베딩한다. 벡터 검색은 원문 텍스트·인덱스 버전·프로필이
맞는 항목만 대상으로 한다. 키워드와 벡터 검색은 동일한 완료 run 목록을 공유하고, 코사인
정확 검색과 RRF를 우선 기준선으로 둔다. 두 점수의 척도를 직접 더하지 않는다.
검색 결과는 기존 payload를 유지하므로 셀·본문 복원과 인용 검사는 기존 경로를 사용한다.

## 대안과 결과

- 별도 벡터 DB 대신 기존 PostgreSQL을 확장하여 원문 항목과 FK·트랜잭션을 공유한다.
- 고정 차원 하나의 컬럼 대신 차원이 명시된 vector 컬럼과 프로필 키로 모델 비교를 지원한다.
- HNSW·IVFFlat 근사 인덱스는 규모·지연·회수율 측정 후 도입한다. 현재 정확 검색은 큰 코퍼스에서 느릴 수 있다.
- 기본 검색을 즉시 교체하지 않고 lexical을 유지하여 마이그레이션·외부 호출 없는 기준선을 보존한다.
- 입력을 몰래 자르지 않는다. 빈 항목·입력 크기 초과는 skipped, 검색 시에는 임베딩 커버리지로 보고한다.

외부 전송은 `--allow-external`과 키가 필요하고 단가는 호출자가 명시한다. 입력 바이트 수에
기반한 보수적 예산 예약, 누적 호출 한도와 실제 사용량 기록을 사용하며 자동 재시도하지 않는다.
본문이나 키·벡터 자체를 호출 감사 파일에 복제하지 않는다. 실패 시에도 가능한 사용량과
예약량을 기록하고 사용량을 받지 못했으면 비용 완전성을 false로 표시한다.

벡터가 전혀 없는 hybrid는 키워드 전용 결과임을 명시하며 dense는 실패한다. DB·API 오류는
성공으로 대체하지 않는다. 부분 커버리지·동일 셀의 반복 조각·모델 버전 변경 가능성·경로 후보
오류·조건 누락은 별도 평가 대상이다. 정확한 벡터 근접 검색은 답변 정확도나 의미 정답 승인이 아니다.

## 추가 결정 (2026-11-10): 로컬 임베딩 공급자

실측 비교 전 개발·평가 단계에서 외부 전송과 비용 없이 벡터 경로를 검증하도록 `provider=local`을 추가한다.

- 로컬은 이 컴퓨터의 Ollama `/api/embed`만 사용한다. 주소는 루프백 http로 제한해 동의 없는 외부 전송을 막는다.
- `truncate: false`로 요청한다. 문맥 길이 초과 입력은 잘라서 저장하지 않고 호출 실패로 기록한다.
- 프로필의 `provider`가 `openai`/`local`로 구분되어 같은 모델명·차원이라도 벡터를 섞지 않는다.
  OpenAI 프로필 구성은 그대로여서 기존 프로필 ID와 저장 벡터는 변하지 않는다. 서버 주소는 프로필에 넣지 않는다.
- 단가는 0으로 고정한다. 호출 수·입력 크기 한도와 감사 기록은 OpenAI와 동일하게 적용한다.
- 웹 화면과 CLI의 기본 공급자는 openai(`text-embedding-3-small`)다. 사용자가 처리 속도를 우선해 선택했다.
  로컬은 CPU 처리 시간 때문에 배치 8개·120초 제한을 쓴다. 답변 생성 모델은 바뀌지 않는다.
- 2026-11-10 개발용 비교(KB 문서 1건, 질문 20개, 정답 위치는 개발자가 정한 임시 기준·사람 검증 아님):
  dense R@5 bge-m3 0.85, OpenAI small 0.75, large 0.70 / 문서 임베딩 시간 122초, 4.9초, 2.6초.
  질문 수가 적어 1문항이 0.05이므로 우열 결론이 아니다. WS2 평가셋으로 다시 비교한다.

실행 명령과 설치 여부 확인은 [RAG_RUNTIME](../RAG_RUNTIME.md), 테스트 구분은
[DEVELOPMENT](../DEVELOPMENT.md)를 따른다. 코드 구현과 실제 DB 설치·유료 호출 완료를 구분한다.
