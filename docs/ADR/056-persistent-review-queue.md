# ADR-056: 오류 담기에서 지속 검토 큐로 연결

2026-11-03 · 로컬 Folio 구현 · 원본/파서/운영 DB 변경 없음

## 문제와 범위

담기는 원본과 의견을 저장하지만 처리 상태와 검수 결과가 연결되지 않았다.
기존 담기 및 정답 참조 이벤트를 읽어 별도 요청을 만들고, 로컬 검사 결과와
진행 이력을 같은 화면에서 조회한다. 멀티에이전트·Astra 의미 Judge·Langfuse
신규 연동·자동 학습·파서 수정은 이번 범위에 포함하지 않는다.

## 저장과 실행

- `work/document-explorer/review-queue/queue.sqlite3`에 요청, 이벤트, 일시정지 설정을 보관한다.
  운영 PostgreSQL과 문서 IR 계약은 유지한다. 현재 서버의 단일 프로세스·작업자 1개 전용이다.
- 입력은 수집 snapshot, 당시 의견·정답 참조·보충 근거를 포함한 불변 JSON 복사다.
  정렬된 입력과 검사기 버전의 해시가 중복 등록 키다. 같은 입력의 재등록은 동일 요청을 반환한다.
  메모·참조가 바뀌면 새 요청을 생성한다. 이전 결과와 당시 입력은 남는다.
- `queued → running → completed / failed / cancelled`와 검사 단계를 별도로 저장한다.
  `completed`는 실행 완료이며 올바른 의미 구조나 Gold 승인이 아니다.
- 시작 시 기존 활성 담기 사례를 등록한다. 담기 이벤트를 outbox로 삼아 등록 실패를
  주기적으로 복구한다. UI가 큐 등록에 실패해도 저장된 담기 기록은 성공으로 보존한다.
- 서버 시작 시 중단된 실행은 interrupted 이벤트를 남기고 재접수한다.
  실패는 자동 무한 반복하지 않으며 사용자가 재시도할 수 있다. 재시도 이력은 누적된다.
- 일시정지는 다음 요청부터 적용한다. 개별 취소는 기존 기록을 지우지 않는다.
  취소 후 늦게 도착한 검사 결과는 상태/시도 번호 확인으로 현재 결과에 반영하지 않는다.
- 보관함의 제외와 요청 취소는 별개다. 제외한 사례에는 새 요청을 만들지 않지만 이미
  접수된 요청을 취소하려면 검토 요청의 취소 버튼을 사용한다.

## 실제 검사와 판단 한계

`review_checks.py`는 네 단계로 원본 해시, 선택 셀/경로 ID, 원문 span, 미해결 병합,
부모 identity 정보를 읽는다. 파서를 실행하거나 PDF를 변경하지 않는다.

경로가 없는 헤더/설명 셀은 정상일 수 있으므로 누락 경로를 오류 확정으로 표시하지 않는다.
Tree에 없는 노드를 참조하면 ID 연결 오류로 기록한다. 사용자가 중첩/문맥/누락을
지적한 경우, 로컬 검사가 정상이어도 원본 대조 필요를 남긴다.

결과는 `suspected_issue`, `insufficient_evidence`, `no_structural_issue_detected`이며,
모든 결과의 `semantic_verified=false`, `training_ready=false`다. 이미지 의미 검수,
전체 정답 셀 대조, 추가 정답 참조의 의미 판정은 미실행이다. API 호출/모델 비용은 0이다.

## 화면

기존 보관함 아래 검토 요청 패널을 추가한다. 2.5초 간격으로 상태를 조회하며
변경이 있을 때만 목록을 갱신한다. 최신 요청을 기본 표시하고 이전 요청도 볼 수 있다.
결과에는 검사 항목·근거 ID·당시 의견·재시도 이력을 표시하며 원본 화면과 정답 참조 편집기로
돌아갈 수 있다. 요청 처리 완료와 사용자 확인 대기를 명시적으로 구분한다.

## 검증

동시 중복 접수, 입력 버전 고정, 담기/IR 보존, 서버 재시작 복구, 지속 일시정지,
실패/취소/재시도 이력, 실행 중 취소 우선, 저장/큐 등록 사이 실패 복구, 해시 불일치,
참조 변경에 따른 새 요청, 토큰 인증과 실제 API 결과 조회를 오프라인 테스트한다.
외부 API는 사용하지 않는다. 기존 저장 자료는 읽기 전용으로 재검사하고 보존 해시를 확인한다.
