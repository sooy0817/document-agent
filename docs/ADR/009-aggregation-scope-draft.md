# ADR-009 (Draft) — 집계 범위와 분류 계층 분리

상태: 제안 초안, 미승인/미구현. 남원 p42/43/51 원본 및 Rule-only 오류에서 도출.
초안은 호출 전에 작성했으며 아래 실제 결과 관찰만 호출 후 추가했다.

## 문제

`parent_child`는 그룹 아래 상세 계정을 표현할 수 있지만 소계가 어느 행들을 집계하는지,
총계가 여러 그룹을 포괄하는지, 조정 항목을 더하는지/빼는지를 명시하지 않는다.
소계를 그룹의 자식으로 넣어도 그룹의 상세 계정과 소계를 동시에 합하면 중복 계산한다.
현재 p43/51에서는 들여쓰기 근거로 소계/총계를 마지막 상세 계정의 자식으로 오인했다.

## 제안

- `parent_child`: 분류/표시 계층으로 한정. 산술 집계의 근거로 사용하지 않음.
- `subtotal_of`: 소계 노드가 가리키는 명시적 `aggregation_scope`와 연결.
- `total_of`: 총계 노드가 가리키는 명시적 `aggregation_scope`와 연결.
- `aggregation_scope`: 원본 노드 ID들의 집합/구간, 제외 항목, 적용 열·기간,
  관련 소계의 참조, source refs, 근거 상태, 후보 대안, 검토 상태를 가진 별도 객체.
- 방향은 `aggregate_node -> scope`로 명시하고 트리의 부모/자식 방향과 혼동하지 않음.
  분류 그룹과 집계 범위는 서로 참조할 수 있지만 동일 객체로 가정하지 않음.
- 조정 계정은 기존 related_adjustment로 유지. 차감/가산 부호는 별도 검증 없이는 미확정.

## 이번 실험의 처리

PhysicalTableIR / StructuredTableIR / Semantic Overlay / Proposal schema는 변경하지 않는다.
모델에 위 신규 relation_type을 허용하지 않는다. 기존 provisional 부모 기대값으로 점수화하되,
소계/총계의 산술 범위를 복원했다고 표현하지 않는다. 총계를 마지막 계정 아래로 연결하지
않고 기권한 경우 오류 관계 제거와 누락을 분리한다. Hybrid에는 삭제 patch 계약이 없으므로
기권만으로 기존 Rule 오류가 제거되지 않을 수 있으며, 모델 제안과 최종 결합 결과를 따로 평가한다.

## 향후 호환성 계획 (미구현)

집계 계약은 별도 버전의 추가 Overlay/sidecar로 우선 도입하고 기존 IR은 그대로 둔다.
기존 소비자가 신규 타입을 받지 않도록 capability/version 협상 또는 별도 endpoint를 쓴다.
기존 parent_child에서 집계 범위를 자동 변환하지 않는다. 원본 근거/독립 검토가 없는 것은
unresolved로 남긴다. 다중 부모 허용으로 트리 Validator를 우회하지 않는다.

필수 검증: 중복 합산, 포함/제외 범위, 중복/누락 source ID, 조정 부호, 반복 소계 이름,
당기/전기 열 혼합, 그룹 경계, cross-page 범위, 순환 집계 참조. 산술 검증과 의미적
집계범위 검증은 별도이며 어떠한 결과도 Fact 적재/발행을 승인하지 않는다.

## 실제 실험 후 관찰

8회 실제 호출에서 Hybrid는 p43 그룹 상세 관계 2개를 복구했지만 소계의 잘못된 부모
3개는 유지했다. p43/p51 총계의 기존 오류도 남았다. p51 LLM-only는 소계 아래 합계를
연결했다. p43 LLM-only의 잘못된 총계 부모가 사라진 것은 집계 범위가 복원됐다는 증거가 아니다.
현재 parent_child의 한계와 삭제 없는 Hybrid 결합의 한계를 별도로 해결해야 한다.
이 관찰은 provisional 골든에 기반하며 본 ADR의 구현/승인을 의미하지 않는다.
