# ADR-068 — 완전한 행 조각 중복 표현과 원본 조건 기반 수정 자동 실행

2026-11-04. 사용자 요청: KB 2쪽 부모 연결을 공통 규칙으로 고치고 원본 기준 성공 조건, 하나은행·농협 회귀, 대시보드 전후 비교까지 실행한다.

## 원인과 수정

물리 표는 이미 존재했다. Native 추출은 아래 표의 머리말을 별도 표로 잡았고, Physical 추출은 본문까지 완전한 표를 만들었다. 기존 중복 표현 검사는 전체 높이를 가진 열 조각만 허용했다. 머리말 조각을 별도 내부 표로 보존하면서 span이 중복되고 읽기 순서가 모호해져 부모 연결 전체가 보류됐다.

`table_understanding/partial_representation.py`에 전체 폭을 가진 행 조각 검사를 추가했다.

1. 기존 1.5pt 오차 내에서 전체 표 폭과 일치해야 한다.
2. Physical의 완전한 셀 영역만 포함해야 한다. 병합 셀을 가르면 거부한다.
3. Native의 공란 padding 조각까지 기존 `native_partition_support`로 분할을 전부 설명해야 한다.
4. 원문 span ID와 셀 좌표 지지, 중복 할당 검사를 모두 통과해야 한다.
5. 공통의 유일한 부모가 있어야 하고 다른 완전한 표와 경쟁하면 보류한다.

원본 후보는 삭제하지 않는다. 별도 감사 기록에서 중복 표현으로 분류하고 내용 구성 시 한 번만 참조한다. 문서명·기관명·페이지·금리·기대 행/열 수는 파서 조건에 없다. PhysicalTableIR·StructuredTableIR·CanonicalDocument 계약은 변경하지 않았다.

## 원본 성공 조건

`work/kb-parent-link-20261104/reference.json`은 PDF 2쪽을 확인해 만든 **원본 검토 초안**이며 사람 승인 Gold가 아니다. 원본 PDF 해시, 부모 셀 ID/bbox, 두 내부 표 ID, 원문 span과 순서 기준이 포함된다. 추출기와 검색에 주입하지 않는다.

| 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 원본 해시 일치 | 충족 | 충족 |
| 두 내부 표가 오른쪽 설명 셀에 연결 | 미충족 | 충족 |
| 각 내부 표 참조 한 번 | 충족 | 충족 |
| 설명·표·주석 span 누락/중복 없음 | 미충족 | 충족 |
| 설명→위 표→주1→아래 표→정의·주2·주의 순서 | 미충족 | 충족 |
| 머리말 중복 표 제거(원본 IR 보존) | 미충족 | 충족 |
| 왼쪽 항목·테두리에 내부 표 오연결 없음 | 충족 | 충족 |

3/7→7/7은 이 참조의 조건 충족 수이며 전체 PDF 정확도가 아니다. KB 2쪽 화면 내부 표는 0→2, 전체 미해결 부모 후보는 2→1이다. 남은 1건은 페이지 테두리 후보로 확정하지 않았다. 행·열 의미 후보는 이번 수정에서 바꾸지 않았다.

## 자동 실행과 반영

`parser_experiments/registered_plan.py`, `source_checks.py`, `engine.py`, `queue.py`:

- 특정 검토 요청의 등록된 수정안·코드 해시·원본 조건을 고정한다.
- 수정안은 허용된 파일에 정확히 일치하는 코드에만 적용한다. 실행/검증은 네트워크 없는 컨테이너에서 한다.
- 수정 전·후 같은 PDF 및 등록 회귀 자료를 전부 실행한다.
- 원문·물리 셀·의미 경로·기존 정상 부모 연결 보존과 대상 원본 조건을 별도로 검사한다.
- 등록 계획이 명시적으로 로컬 적용을 요청한 경우에만 통과한 후보를 반영한다. 실행 중 원본 코드가 변하면 차단한다. 원본 코드·IR·결과는 보존한다. push/deploy는 하지 않는다.
- 이미 반영한 동일 수정안은 다시 변경하지 않고 최신 결과 비교로 전환한다.
- 새로운 수정안을 스스로 발명하는 무한 루프는 아니다. 이번 수정안은 코드 분석으로 준비했으며 모델 호출은 0회다.

이번 실행은 기존 자동 큐에 `6009c6e097034a879d7a6d54dacf6b3a` 의견을 접수해 수행했다. 수정안 자동 격리 실행 후 같은 검사 게이트를 사용하는 `--apply-passing`으로 로컬 반영했다. 이후 등록 계획은 `apply_to_workspace`로 마지막 단계까지 묶을 수 있다.
