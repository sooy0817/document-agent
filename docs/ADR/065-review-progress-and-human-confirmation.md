# ADR-065: 의견 재검토 진행 표시와 원본 대조 확인 완료

2026-11-04 · 기존 IR/파서/모델 프롬프트 변경 없음.

## 결정

1. 큐 조회에 `submitted_opinion`을 추가하여 자식 실행이 실제로 받은 의견을
   표시한다. 부모 화면에서도 `decision.child_id`의 현재 상태를 표시한다.
   접수/대기/실행/실패/결과 저장을 구분하고 비교 수치는 정확도 향상으로 표시하지 않는다.
   역할 분류에는 의견을 주입하지 않는 기존 구현도 화면에서 명시한다.
2. 병합, 제목/본문 역할, 값/문자/단위/기간, 설명/조건/주석, 계속표 유형을
   기존 관찰 유형에 추가한다. 기타 및 판단 불가를 유지한다.
3. 새 `POST /api/review-queue/{id}/confirmation`은 모델을 호출하지 않는다.
   `confirmed`, `note`, `source_ids`를 받아 선택 범위에 대한 사람의 원본 대조
   확인만 별도 SQLite `confirmations` 테이블과 이벤트에 추가한다.
4. 빈 source_ids는 해당 요청의 원래 선택 범위다. 셀 ID가 지정되면 그 셀만
   확인하며 영역 전체 알림을 해제하지 않는다. 전체 선택 범위를 확인한 경우만
   알림을 해제하고 다음 미확인 요청으로 이동한다.
5. `applies_to=saved_source_display`, `model_candidate_applied=false`를 기록한다.
   이 동작은 Canonical/Structured 의미 승인, 모델 제안 적용, 금융 사실 발행이 아니다.
   선택 영역의 사람이 한 검토만 기록하며 전체 문서 정확도로 집계하지 않는다.
6. 기존 decisions와 requests/result는 보존한다. 같은 확인 재전송은 멱등적이다.
   확인 취소도 새 이벤트로 남긴다. 최신 완료/실패 요청만 확인할 수 있으며,
   확인 완료 후 재검토하려면 먼저 취소해야 한다.

## 검증 범위

확인 저장/취소/동시 재전송/셀 범위/잘못된 ID/구 요청 차단, 의견 전달 및 기존
재검토 비교를 오프라인 검사한다. 실제 문서에 임의로 '맞음' 승인을 쓰지 않는다.
운영 문서 판단은 사용자가 직접 입력한다. 파서/생성 모델의 정확도 실험은 이번 범위 밖이다.

## 완료 목록과 재검토 변화 표시 (2026-11-04)

- 기본 '남은 검토 요청'은 전체 선택 범위 확인을 마친 최신 요청을 숨긴다.
  '완료 이력'과 '전체 이력'은 기존 기록을 조회하며 삭제는 없다. 셀 일부 확인은 남긴다.
- 화면의 전후 비교는 부모 실행을 거슬러 마지막 완료 결과를 기준으로 한다.
  중간 실패는 빈 정답으로 비교하지 않는다. 원본 PDF 및 Canonical 해시가 같고
  두 실행 모두 의미 후보가 있는 경우에만 역할/행·열 ID·상태/문맥 ID 변화 수를 센다.
- 셀 인용, 이전/새 후보, 판정 이유, 남은 코드 검사를 표시하고 '원본 JSON 동일'과
  모델 후보 미적용 상태를 분리한다. 모델 인용은 독립 검증된 원문 명칭으로 표시하지 않는다.
- 기존 result.comparison은 수정하지 않는다. 화면에서 재계산한 기준과 차이를 보여준다.
- 의견 작성 중에도 실행 결과는 갱신하며 미제출 입력은 보존한다.
- JS 17개 검사 및 실제 저장 결과 재생으로 검증. 모델 호출·파서 변경 없음.
