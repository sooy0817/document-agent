# ADR-059: 원본 축 해석과 저장 관계 조회의 분리

2026-11-03 시작, 2026-11-04 결과 정리. 실험 전용이며 자동 큐/파서/IR에는 적용하지 않는다.

## 변경

`demo/review_focus.py`의 LangGraph는 `interpret_axes → judge_axes → storage_lookup_and_validation`이다.
모델 두 단계는 원본 crop·셀 ID·원문·좌표와 선택 대상만 받는다. 사용자 오류 주장, 기존 의미
경로, 저장 여부는 전달하지 않는다. 이후 코드가 제안된 관계의 실제 저장 여부를 조회한다.
저장돼 있지 않다는 이유로 원본 의미 후보를 부정하지 않으며, 저장돼 있다는 이유로 승인하지 않는다.

선택 표, 기존 부모/계속표 참조, 기하적 포함 영역, 가까운 위쪽 정렬 조각과 주변 span을
후보 문맥으로 모은다. 부모/계속표 참조는 선택에 사용되므로 완전한 파서 독립 검토는 아니다.
같은 페이지의 다른 표를 무조건 전부 넣지 않는다. 셀/근거 80개, 대상 셀 12개, 입력 100KB,
인접 설명 span 12개로 제한하며 누락과 비검토 대상을 별도 기록한다. 전체 문서 검토가 아니다.
표 전체를 선택해도 내부 표의 모든 값 셀까지 검사했다고 표시하지 않는다.

모델은 각 대상의 역할, 양축의 explicit/contextual_candidate/no_header/unknown,
전체 헤더 후보 ID, 원문 인용과 이유를 반환한다. `no_header`를 정상 상태로 허용하되 근거를
요구한다. 코드의 좌표 검사는 행/열 방향 모순을 잡는 필요조건이며 의미 정답의 증명이 아니다.
다른 물리 조각의 헤더는 즉시 오답으로 처리하지 않고 계속성 확인 대상으로 보류한다.
최종 semantic_verified/training_ready는 항상 false다.

## 재생 검사와 실제 실행

원래 기록의 후보를 수정하지 않고 새 검사에 재생한다. 범위 밖 후보는 오답으로 집계하지 않는다.
하나은행의 정상 행 후보는 유지했고, 가입대상을 열 헤더로 부른 후보와 자기 소속을 중첩 관계로
부른 후보를 차단했다. 새 입력에 대한 모델 성능은 별도로 실제 API 6회로 확인했다.

개발/회귀 3문서, 문서당 GPT-4.1 2회. 입력 근거 개수 KB 164→31, 하나은행 303→13,
농협 266→27. 하나은행/농협의 직접 행·열 라벨은 원본 시각 검토와 맞았으나 값 셀 인용 누락으로
보류됐다. KB는 긴 셀을 description으로 처리하며 왼쪽 항목과의 관계를 비웠고 Judge도 동의했다.
코드가 KB를 보류한 이유는 인용 불일치이며, 의미 누락을 직접 검출한 것은 아니다.

3/3 보류는 100% 정확도를 뜻하지 않는다. 범용성·전체 Tree·주석 적용·독립 Gold 정확도는
미평가다. 실험 코드 동결 후 결과에 맞춰 프롬프트나 검사기를 수정하지 않았다.
기존 큐 기본 설정/과거 결과는 유지한다. 실제 모델은 `gpt-4.1-2025-04-14`; mini로 바꾸지 않았다.
실행 명령·원본/JSON·Trace·비용은 `reports/review-focus-20261103/comparison.html`에 있다.

## 남은 문제

역할 분류를 관계 생략의 근거로 사용하면 긴 셀의 설명이 행 항목과 분리된다. 다음 실험은
역할과 관계를 독립 출력하고 description도 양축/상위 항목 적용 가능성을 검수해야 한다.
또한 셀 ID로 조회할 수 있는 원문 값을 모델이 반복 인용해야 하는지 검토하되, 현재 결과의
보류를 사후 해제하지 않는다. 사용자 확인 Gold와 정상/오류 양쪽 분모가 먼저 필요하다.
