# 기존 Rule과 개선 Rule 후보 이해하기

작성 기준: 2026년 10월 19일. 남원축협 개발셋 7개 표의 오프라인 비교 결과.

**이번 개선은 원본 PDF의 숫자를 다시 추출하는 작업이 아니라, 이미 추출한 표에서 어떤 행이 어떤 그룹에 속하는지 추가로 추론하는 작업이다.** 기존 Rule을 전면 교체한 것이 아니며, 별도로 켜서 평가하는 후보 생성 규칙을 추가했다. 새 LLM 호출은 없었다.

## 1. Rule과 Tree는 무엇인가

| 용어 | 쉬운 설명 |
|---|---|
| Rule | 프로그램이 관계를 판단할 때 사용하는 규칙 |
| Tree | 그 판단으로 만든 상위 항목과 하위 항목의 연결 구조 |
| 기존 Rule 결과 | 개선 규칙을 추가하기 전의 자동 판단 결과 |
| 개선 Rule 후보 | 표의 연속된 행 배치를 추가로 살펴 제안한 관계를 반영한 실험 결과 |
| 기존 Hybrid | 이전 실제 LLM 응답과 Rule을 결합한 결과. 이번 개선 Rule 후보와는 별개 |
| 검토용 정답 Tree | 원본을 보고 작성한 비교 기준. 자동 예측 결과와 구별해서 관리 |

예를 들어 `대출금 → 일반대출금`은 “일반대출금이 대출금 그룹에 속한다”는 관계다. 숫자 자체와 이 관계는 따로 저장한다. 관계가 틀렸다고 원본 숫자까지 바꾸지 않는다.

## 2. 무엇이 달라졌나

기존 구조 분석에는 병합 셀의 점유 범위 같은 물리적 근거가 있고, 의미 관계를 제안하는 기존 규칙도 있다. 하지만 **병합이나 번호가 없는 그룹 제목 아래에 상세 행이 이어지는 표**에서는 부모 관계를 충분히 복원하지 못했다.

새 규칙은 다음과 같은 행의 흐름을 추가로 본다.

| 확인하는 정보 | 새 규칙의 처리 |
|---|---|
| 왼쪽 항목명은 있고 나머지 값 열은 비어 있음 | 다음 행에 값이 있으면 그룹 제목 후보로 봄 |
| 그 아래에 값이 있는 행들이 이어짐 | 해당 그룹의 자식 후보로 연결 |
| 다음 그룹 제목 후보가 나타남 | 이전 그룹을 끝내고 새 그룹으로 전환 |
| 상세 행 뒤에 항목명 칸이 가로 병합된 행이 나타남 | 그룹 종료 가능성을 기록. 소계라고 확정하지 않음 |
| 표의 마지막 일반 행이 상세인지 총계인지 불분명함 | 부모 연결을 기권 |
| 좌우 병렬표 또는 항목명 열이 여러 개임 | 이번 추가 규칙은 적용하지 않음 |

여기서 “값이 있음”은 값 열에 원문 텍스트가 있는지를 뜻한다. 숫자의 의미나 합계 계산을 이해했다는 뜻은 아니다. 기관명, 페이지 번호, 연도, 특정 계정 이름으로 정답 관계를 만들지 않는다.

## 3. 예시로 이해하기

다음은 동작 설명용 단순화 예시이며 실제 평가표를 그대로 옮긴 것은 아니다.

| 항목 | 금액 칸 |
|---|---|
| 그룹 A | 비어 있음 |
| 상세 항목 X | 값 있음 |
| 상세 항목 Y | 값 있음 |
| 그룹 B | 비어 있음 |
| 상세 항목 Z | 값 있음 |
| … | … |

기존 결과에서 X와 Y의 부모가 빠졌다면, 추가 규칙은 행 배치를 근거로 다음 관계를 제안한다.

```text
그룹 A
├─ 상세 항목 X
└─ 상세 항목 Y

그룹 B
└─ 상세 항목 Z  ← 후속 배치와 종료 조건도 확인해서 제안
```

항목 이름을 다른 문자열로 바꿔도 같은 배치라면 같은 관계를 제안하도록 만들었다. 다만 “그룹 A”처럼 보이는 행이 사실 금액이 누락된 일반 상세 행일 수도 있다. 그래서 자동으로 정답 처리하지 않는다.

**그룹 소속과 합계 범위는 다르다.** “X와 Y가 A에 속한다”를 알아도 “소계가 정확히 어떤 값들을 더한 것인가”까지 검증한 것은 아니다. 소계·총계의 적용 범위는 별도의 집계 관계로 확인해야 한다.

## 4. 어떤 순서로 처리하고 저장하는가

```text
원본 PDF
  → DocumentIR: 추출한 문자와 위치
  → PhysicalTableIR: 표의 셀, 경계, 병합 범위
  → StructuredTableIR: 행·열 구조와 셀 연결
  → 기존 Rule 관계
       + 새 그룹 범위 규칙의 관계 후보
       → ID Binder: 원본 노드·셀에 정확히 연결
       → Validator: 참조·충돌 등 검사
       → 별도 관계 수정안과 적용 전후 결과 저장
```

원본 추출 결과를 덮어쓰지 않는다. 원래 숫자·문자·좌표와 기존 결과를 보존하고, 새 관계와 검사 결과를 별도로 남긴다. 이번 실험의 43개 수정 연산은 모두 `review_required`다.

| 상태 | 의미 |
|---|---|
| observed | 원본 물리 구조에서 관찰한 근거 상태 |
| inferred | 배치 등을 바탕으로 추론한 상태 |
| unresolved | 근거가 부족하거나 충돌하여 해결하지 못한 상태 |
| review_required | 관계를 사람이 검토해야 하는 상태 |

이 상태들은 모두 같은 종류의 점수가 아니다. 원본 경계 상태와 의미 관계의 검토 상태를 구분해 보존한다. Validator를 통과했다고 의미상 정답이 되거나, inferred가 observed로 승격되는 것은 아니다. 미검증 관계를 확정 Financial Fact로 발행하지 않는다. 실제 PostgreSQL 적재는 아직 진행하지 않았다.

## 5. 현재 비교 결과와 퍼센트 읽는 법

아래는 **동일한 남원 7개 표와 동일한 정답 주석**을 사용한 비교다. 이전 3개 표 비교 또는 14개 Hard-case 비교와는 평가 범위가 다르므로 숫자를 직접 이어 붙이면 안 된다.

| 지표 | 기존 Rule | 개선 Rule 후보 | 의미 |
|---|---:|---:|---|
| 부모 관계 Precision | 9/25 · 36.0% | 48/57 · 84.2% | 제안한 연결 중 맞는 연결의 비율 |
| 부모 관계 Recall | 9/48 · 18.8% | 48/48 · 100% | 필요한 연결 중 찾아낸 비율 |
| 전체 행 경로 일치 | 25/73 · 34.2% | 59/73 · 80.8% | 최상위부터 해당 항목까지 경로 전체가 맞는 비율 |
| 열 경로 일치 | 30/30 · 100% | 30/30 · 100% | 평가한 열 경로가 맞는 비율 |
| 셀의 행·열 경로 일치 | 70/233 · 30.0% | 173/233 · 74.2% | 각 값 셀이 올바른 문맥에 연결되는 비율 |
| 근거 일치 | 231/233 · 99.1% | 231/233 · 99.1% | 평가 기준의 원본 근거와 대응하는 비율 |

**Recall 100%는 완성됐다는 뜻이 아니다.** 필요한 부모 연결 48개를 모두 찾았지만, 제안한 57개 중 9개는 잘못된 연결이다. 잘못된 상위 연결이 남으면 그 아래 셀도 잘못된 전체 경로를 가질 수 있다. 따라서 셀 경로 정확도는 74.2%다.

이번 비교에서는 행 경로 34개와 셀 경로 103개가 개선됐고, 기존에 맞았던 경로가 틀리게 된 사례는 없었다. 여전히 행 경로 14개, 셀 경로 60개가 불일치한다. 이는 남원 개발셋에서의 진단 결과이며 새 기관 문서에서의 정확도는 아직 평가하지 않았다.

## 6. 정답 Tree를 맞다고 검토했는데 왜 점수가 낮은가

사용자가 확인한 것은 **비교 기준으로 사용할 정답 Tree**이고, 위 점수는 **자동 생성 결과가 그 기준과 얼마나 일치하는가**다. 정답 Tree가 올바르더라도 자동 결과가 부모를 누락하거나 잘못 연결하면 점수가 낮다.

화면의 Tree 검토와 모든 셀 좌표의 독립 검토도 다르다. 현재 검토 이력은 보존하지만, 모든 JSON과 좌표가 독립적으로 검증됐다고 표현하지 않는다.

특히 p45의 `4,361,381`, p46의 `4,315,397`은 기존 PhysicalTableIR에 이미 있었다. 이전에 금액 누락으로 설명한 부분은 정정한다. 넓게 표시한 정답 셀 영역이 빈 셀과 대응되거나 바인딩되지 않아 평가상 누락처럼 보였던 문제다. 숫자를 다시 만들거나 옮길 일이 아니라, 원본 병합 범위와 정답 영역의 대응을 확인할 일이다.

## 7. 아직 해결되지 않은 부분과 다음 검증

1. **셀 경로 60개 불일치부터 확인한다.** 잘못된 부모, 열 의미, 정답 영역 대응 중 어디서 발생했는지 나눈다. RAG가 다른 항목·기간의 금액을 가져오는 위험과 직접 연결된다.
2. **잘못된 기존 부모 9개를 검토한다.** 부모가 없다는 근거 없이 기존 관계를 지우거나 정상 루트라고 선언하지 않는다.
3. **소계·총계의 적용 범위를 별도로 평가한다.** 이번 규칙의 그룹 종료 추정만으로 집계 검증을 완료했다고 하지 않는다.
4. **빈 값과 표의 마지막 행 예외를 검증한다.** 빈 상세 행을 그룹으로 오해하거나, 실제 마지막 상세 행을 기권할 수 있다.
5. **새 문서로 일반화를 확인한다.** 남원은 개발·회귀용으로 유지하고 남평은 최종 Holdout으로 남긴다. 새 문서 결과를 보기 전에 코드와 설정을 고정한다.

RAG 임베딩·답변 실험은 Tree 평가 이후에 진행한다. 이번 결과는 새 LLM의 의미 판단 능력이 개선됐다는 증거가 아니라, 추가한 결정적 규칙이 이 개발셋의 누락 관계를 줄였다는 결과다.
